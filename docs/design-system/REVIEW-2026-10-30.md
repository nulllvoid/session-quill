# Fieldnotes design-system review

Reviewed the production dashboard, implementation contract, generated tokens, opt-in components, and interactive reference using UI Skills `baseline-ui` and `fixing-accessibility`. Quill's existing CSS, native controls, evergreen palette, and Geist typography remain the foundation.

## Assessment

The system has a coherent visual identity and useful semantic color roles. Theme tokens come from the production stylesheet, and existing contrast tests cover text, status colors, focus indicators, and control boundaries. The main weaknesses were incomplete keyboard behavior, small touch targets, and a reference page that overstated its parity with production. These warranted targeted fixes, not a new UI framework or visual redesign.

## Findings and fixes

| Finding | Evidence before the change | Resolution |
| --- | --- | --- |
| Sidebar tab semantics lacked keyboard behavior | `role="tab"` controls had no arrow-key handler; all were Tab stops; `#main` lacked its selected-tab label | Roving focus, orientation-aware arrows, Home/End, panel labelling, and focus after navigation. Hidden phone tabs are skipped; More remains reachable. |
| Dialog focus could return to the wrong control | `closeDialog()` focused shared `lastFocus`; opening Help before Run agent reproduced a return to Help | Let the native dialog restore its own trigger instead of overriding it with drawer state. |
| Phone targets contradicted the 44px guidance | Browser measurements found 30px action buttons and a 32px search field; detail navigation used 28px buttons | Coarse-pointer rules enlarge action/copy buttons, filter tokens, tabs, search, and selects. Mobile toolbar labels use 13px rather than 11px. |
| Long titles obscured evidence | Sticky `.detail-head` covered the Activity tab when scrolling a long ticket title | Only the detail navigation remains sticky; the title and metadata scroll normally. |
| Reference tabs skipped their content | Pressing Tab after selecting Live skipped the panel | Reference panels now have `tabindex="0"`. |
| Reference toggle name changed with its pressed state | The theme button changed from “Dark theme” to “Light theme” while `aria-pressed` became true | Keep “Dark theme” as the stable toggle name and expose state through `aria-pressed`. |
| Icon fetching delayed unrelated reference controls | Top-level `await` loaded each SVG before registering tab and demo handlers | Load the catalog independently; preserve an icon search entered while loading. A held-manifest browser test covers this. |
| Reference and documentation had drifted | The reference said version 1.0 and “The shipped Runs page”; its example omitted production behavior; spacing omitted 20px | Align the guide and reference at 1.3, label the Runs example as simplified, restore the spacing step, and refresh both preview images. |

## Validation

- 251 UI/export tests passed, including theme contrast and export privacy checks.
- 18 Chromium browser tests passed with no captured page errors.
- Dashboard and reference layout checks at 390, 1024, 1280, and 1440px in light and dark themes; long ticket content, keyboard flows, and coarse-pointer targets covered separately.
- All 50 generated assets verified without regeneration; no token values or runtime dependencies changed.

The `q-*` reference kit remains opt-in; it is not the dashboard's component implementation. Compact desktop controls still vary in size. This review did not perform a screen-reader audit, Safari/Firefox testing, or a full backend test run, and does not certify complete accessibility compliance.
