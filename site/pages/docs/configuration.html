Configuration

Two files. ~/.claude/quill/config.toml is yours. A repository's .quill.toml is shared with the team and can tighten your settings but never loosen them. Secrets go in neither; name an environment variable instead.

Which file wins

The worker picks up edits to either file within about ten seconds. A .quill.toml that cannot be parsed makes its repository strict with no tracker until it is fixed.

[tracker]

[tracker]
system           = "jira"                        # jira | linear | github | custom
domain           = "https://example.atlassian.net"
url_template     = "{domain}/browse/{key}"       # linear: "{domain}/issue/{key}" · github: "{domain}/{repo}/issues/{number}"
key_pattern      = '\b([A-Z][A-Z0-9]+-\d+)\b'    # the default; single quotes keep backslashes literal
prefixes         = ["PROJ", "OPS"]               # empty = any key except common tokens like UTF-8
sources          = ["prompt", "branch"]
on_new_key       = "switch"                      # switch | add | ignore
sync_token_env   = "JIRA_TOKEN"                  # github: GITHUB_TOKEN with repo = "owner/name" · linear: LINEAR_API_KEY
sync_username_env = "JIRA_EMAIL"                 # Jira Cloud only
write_back       = false                         # opt-in; quill tracker push previews, --confirm sends
import_assigned  = false                         # 1.0: tracker-sync imports issues assigned to you (Jira, GitHub)
auto_clone_dir   = "~/src/quill"                 # 1.0: consented clones land here
clone_hosts      = ["github.com", "gitlab.com", "bitbucket.org"]
environments     = ["staging", "production"]     # default environments for repositories without their own

[tracker.status_map]                             # optional, with write_back; defaults: To Do, In Progress, In Review, Done
review = "Code Review"

[tracker.repo_map]                               # 1.0: the resolver's first rule
PAY        = "payments-api"                      # a Jira project key or component, or a GitHub owner/repo
"acme/web" = "https://github.com/acme/web.git"   # a registered repo id or a remote URL

How a ticket finds its repository

  1. [tracker.repo_map]: the Jira project key or component, or the GitHub owner/repo, mapped to a registered repository id or a remote URL.
  2. A registered repository whose origin matches a repository URL in the issue's linked development data (the issue's own repository on GitHub; remote links or the dev panel on Jira).
  3. A clone under auto_clone_dir or a known repository root whose origin matches, comparing https and ssh forms as one.

The result is linked, needs-clone (remote known, no local clone) or none. A needs-clone ticket shows the chip and a Clone… button; nothing clones on its own. The owner can tag a ticket quill/no-code to tell the resolver to skip it.

Clones are refused for URLs with credentials, hosts outside clone_hosts, file: and ext:: transports, and targets outside auto_clone_dir. The same remote is never cloned twice.

[gate]

[gate]
mode = "nudge"            # off | nudge | strict
  • off: capture only.
  • nudge (default): nothing is denied. When an unbound session changes files or commits, the next Stop asks Claude once which ticket the work belongs to.
  • strict: covered mutating tools are denied until the session is bound, and denied whenever the binding snapshot or the worker is unavailable. A mention only binds when prefixes is set.

[repos.<id>]

[repos.payments-api]
provider        = "github"         # github (gh signed in) | bitbucket (with token_env)
deploy_on       = "merge"          # treat a merged PR as the deployment; omit for per-environment obligations
test_command    = "npm test"       # 1.0: the worker's test gate for attempt-fix runs
test_timeout_ms = 600000           # default ten minutes

[repos.billing]
provider     = "bitbucket"
token_env    = "BITBUCKET_TOKEN"   # sent as a bearer token; username_env switches to an app password
# provider_url = "https://bitbucket.example.com"   # Bitbucket Server; omit for bitbucket.org

quill repo add <path>, quill repo list and quill repo remove <id> register repositories and record their path and default branch for you; the id comes from the folder name. Inside a linked git worktree, registration points at the repository's main working tree.

[handoff]

[handoff]
max_concurrent_readonly = 2
max_concurrent_fix      = 1

Read-only runs and runs with edit_source are counted separately; fixes on one repository stay one at a time.

Dashboard port

ui_port = 47321           # 1.0 default; 0 keeps a random port

The server tries the fixed port first and falls back to a random one when it is taken. Host, port and pid are recorded in ui-endpoint.json, which the status line reads.

[[schedule]]

[[schedule]]
name  = "reconcile"
job   = "reconcile"       # reconcile | agent | digest | publish | tracker-sync
every = "2h"              # or 30m, 1d

[[schedule]]
name = "evening-sync"
job  = "reconcile"
cron = "30 19 * * 1-5"    # in the store's time zone

Without configuration the worker reconciles every two hours. A run missed while the computer was off runs once when the worker starts.

[[publish]]

[[publish]]
name          = "team"
kind          = "artifact"       # artifact | markdown | html (with path = "...")
projects      = ["my-project"]
fields        = ["key", "title", "status", "next", "pr", "deployments", "updated"]
include_links = false
on            = ["reconcile"]
two_way       = true

[publish.team]
auto_run_editors = ["priya@example.com"]   # 1.0: these editors' Run agent edits queue without approval
auto_run_recipes = ["analyse", "deploy-check"]   # read-only recipes only

The first publish to a destination waits for your confirmation. With two_way, editors change status and next action on the page and, from 1.0, pick a recipe under Run agent; each becomes a revision-checked request or a proposed run on your dashboard.

[mirror]

[mirror]
enabled = true

The owner's worker keeps a sanitised dashboard and snapshot in <store>/.quill-mirror; quill mirror status|open reads it on any machine.

Worker commands

quill worker install      # start at login (Task Scheduler, LaunchAgent or systemd user unit)
quill worker uninstall
quill worker stop         # pause processing and automatic restart
quill start               # resume
quill ui --revoke         # clear every dashboard session
quill doctor
