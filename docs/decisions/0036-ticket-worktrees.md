# ADR 0036 — Ticket worktrees and their teardown

Date: 2026-10-21 · Status: accepted · Builds on [ADR 0001](0001-single-writer-cli.md), [ADR 0005](0005-gate-modes-and-auto-binding.md), [ADR 0021](0021-pr-closes-its-tickets.md) · PRD FR-1.1, FR-1.3 as amended by `docs/research/2.0.0/01-gap-analysis.md`

## Context

Worker runs already get an isolated checkout: a detached worktree under `<quillHome>/handoffs/worktrees/<run>` that the worker removes after the run (`--force` is acceptable there because the checkout is the worker's own and its patch is collected first). Interactive sessions get nothing: two sessions on two tickets in one repository share one checkout, so their edits, branches and test runs collide. The PRD asked for `quill start <ticket>` to provision a worktree; `quill start` takes no ticket (it enables tracking), and the ticket commands are `quill ticket work` and `quill ticket bind`.

The hard constraint is that a teardown must never delete a person's uncommitted work.

## Decision

- **Opt-in mount from the ticket commands.** `quill ticket work|bind ... --worktree` (or `[worktree] auto = true`) mounts a ticket worktree after the binding. `--no-worktree` skips it under `auto`. An explicit `--worktree` that cannot be honoured (no repository, a foreign folder at the path, a refused branch) fails the command with the binding already made; `auto` only prints why there is no worktree. Inside an agent run the CLI refuses these commands ([ADR 0026](0026-autonomous-access-and-guard.md)), so worker runs never get one; their credentials go through `cred-env`, not copied env files.
- **Location and branch.** `<quillHome>/worktrees/<repo_id>/<KEY>`, outside the repository so no editor, test runner or `git clean` in the repository sees it. Branch `quill/<KEY>`, checked with `SAFE_BRANCH`, `git check-ref-format --branch` and `isProtectedBranch`. An existing `quill/<KEY>` (an earlier worktree's, kept on teardown) is checked out as it is; otherwise the branch starts at the ticket's latest recorded branch (local, or origin's tip when the local copy is only behind), else the repository's HEAD (`worktreeBase`, the same rule runs use). Nothing is forced or reset.
- **Reuse.** A folder already at the path is reused only when git lists it as a worktree of that repository and it is on `quill/<KEY>`; anything else there is left alone and the command fails.
- **Env files are copied, never linked.** `[worktree] copy` (default `.env`, `.env.local`) lists repository-relative paths. An entry is refused when it is absolute in any spelling, contains a `..`, `.git` or empty segment. A file is copied only when `lstat` says it is a regular file (no symlinks), its real path stays inside the repository, `git check-ignore` reports it ignored (a tracked file is never copied), and the destination does not exist and its folder resolves inside the worktree (a tracked symlinked folder cannot carry the copy out). Copies use `COPYFILE_EXCL`.
- **Switching is Claude's job.** The CLI prints `Worktree path: <path>` and `Switch into it before editing: cd "<path>" ...`; the `session-quill:ticket` command text tells Claude to switch into that path (its shell or its worktree tool) and make every edit, test and commit there. A session started inside the worktree is attributed to the repository with no git process on the hook path: `scopeFor` already resolves a linked worktree through its `.git` file (ADR 0021's branch capture reads `quill/<KEY>` the same way).
- **One ingress event kind, `worktree`.** Payload `{ op: 'mounted'|'pruned'|'kept', mount_id, ticket_id, repo_id, path, branch, base_sha, reason? }`. The CLI emits `mounted` (and `pruned` for `quill worktree remove`) through the normal ingress path and waits for the worker's acknowledgement; the worker emits `pruned` and `kept` from its sweep with `Worker.emit`. The reducer keeps `ticket.worktrees[]` (at most 10 records; pruned ones are dropped first), does not bump the ticket's revision (machine state, not an owner edit) and treats the same folder mounted twice as one record.
- **Source identity `worktree:<ticket_id>:<op>:<path>:<mount_id>`.** The plan's `worktree:<ticket_id>:<op>:<path>` would make a second mount of the same folder after a teardown (a reopened ticket) a duplicate that the reducer drops, and would leave the worker re-emitting a `kept` it can never record. Each mount gets a fresh `mount_id` (a UUID) and its `pruned`/`kept` events name it, so each op still happens once per mount.
- **Teardown sweep.** The worker sweeps at start and then at most hourly from the handoff extension's tick (`src/handoff/ticket-worktrees.js`). A worktree is due when its ticket is done and neither the ticket (`updated_at`) nor the mount changed for `[worktree] keep_days` (default 7), and no live or idle session (not ended, not extinct) started inside it or is bound to the ticket. There is no recorded "done since" time, so the ticket's last change stands in for it: any later change only makes the worktree stay longer. Before git runs, the recorded path must be inside `<quillHome>/worktrees` and git must list it as a worktree of the repository; otherwise nothing is touched. Then:
  - `git status --porcelain --untracked-files=all` non-empty: kept, reported once with reason `uncommitted-changes`;
  - a detached HEAD whose commit no local or remote branch contains: kept, reason `detached-head` (an addition to the plan: removing it would orphan those commits);
  - otherwise `git worktree remove <dir>` without `--force` (git itself refuses a dirty or locked worktree, so a change made between the check and the removal is still safe), then `pruned`. Ignored files such as the copied `.env` go with the folder.
  - A removal that fails (a Windows lock) records nothing and is retried by the next sweep. The branch is always kept (ADR 0021 finds PRs by branch).
  A kept worktree is checked again on each sweep and pruned once it is clean. A ticket reopened before the sweep keeps its worktree; reopening after teardown starts nothing, and nothing already done is undone.
- **CLI.** `quill worktree list [--all] [--json]` shows each recorded worktree with the folder's state on disk (clean, uncommitted changes, detached HEAD, missing). `quill worktree remove <KEY>` applies the same checks as the sweep, refuses a dirty worktree with "commit, stash or discard them first (there is no force option)", refuses when run from inside the worktree, and always keeps the branch. The plan's `--keep-branch` flag is not added: the branch is never deleted, so there is nothing for it to change.
- **Configuration is user-only.** `worktree` joins `USER_ONLY_FIELDS`: a repository's `.quill.toml` cannot choose which files are copied out of the repository or how soon a worktree goes.
- **Local only.** `ticket.worktrees[]` holds local paths. It is in the owner's snapshot and ticket detail, never in an export, the mirror, a publisher payload or a vault note (`frontmatterFor` drops it); `tests/export/privacy-sentinel.test.js` covers it.

## Consequences

- Two sessions can work on two tickets of one repository at once without sharing a checkout, and the repository's own checkout is never switched.
- Worktrees accumulate until their tickets are done and a week has passed; a worktree with uncommitted work stays until the person deals with it, and `quill worktree list` shows why.
- `quill/<KEY>` branches accumulate in the repository; deleting merged ones is left to the person (`git branch -d` refuses unmerged ones).
- The sweep costs one `git worktree list` and one `git status` per due worktree per hour.
- A session that `cd`s into a worktree after starting elsewhere is not seen by the live-session check (hook events carry no later cwd); the clean-status check and git's own refusal still protect its work.

## Alternatives considered

- **Mount from `quill start`.** Rejected: `quill start` enables tracking for a repository and takes no ticket; overloading it would change a command the setup skill depends on.
- **Worktrees inside the repository (`.claude/worktrees`).** Rejected: tools in the repository (test runners, watchers, `git clean -fdx`) would see them, and a repository-relative location needs the repository's ignore rules to cooperate.
- **Symlink env files.** Deferred: a link lets an edit in the worktree change the repository's file and points outside the worktree; copies are predictable.
- **Reuse `removeWorktree` for teardown.** Rejected: it uses `--force` and falls back to deleting the folder, both acceptable for a run checkout and never for a person's worktree.
- **A worker-only `worktree` kind.** Rejected: the CLI is the one that mounts. Forging an event through ingress can at most hide a worktree from the sweep or name a path the sweep then refuses (outside the root, or not a registered worktree), so the kind stays an ingress kind as reserved.
