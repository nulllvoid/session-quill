The work around your work.
Taken care of.

From your assigned queue to a verified result, one local worker keeps the pieces connected. You decide what runs.

Zero-touch workspace

Assigned to you.
Prepared for you.

Turn on import_assigned and tracker sync pulls the Jira or GitHub issues assigned to you into tickets, with no agent in the loop. A rule-based resolver links each ticket to a repository: your repo_map first, then the repository the issue itself names, then a clone it finds under auto_clone_dir.

When the remote is known but there is no clone, the card says Needs clone. One confirmation clones it over https or ssh from an allowed host, registers it, and links the ticket. Nothing clones on its own.

The worker starts at login with quill worker install, listens on a stable port, keeps you signed in across restarts, and puts the dashboard link in your status line.

  • Jira and GitHub assigned-issue import, idempotent
  • Clone hosts default to github.com, gitlab.com and bitbucket.org
  • Windows, macOS and Linux login entries, no admin rights

Verified agent pipelines

Measured. Gated.
Self-checked.

Every run records its own timings: queue wait, worktree setup, agent time, test time. A run that may edit source always gets a self-check turn, whatever its recipe says.

Give a repository a test_command and the worker itself runs it in the run's worktree after the agent finishes. It records the exit code, duration and output as evidence, grants exactly one repair turn on failure, and surfaces no suggestion if the tests fail again. Without a test command the run says so: fixes are not test-verified.

Read-only and source-editing runs have separate concurrency caps, and fixes on one repository still go one at a time. Large analyses split by module inside a single run and merge their findings.

  • Timings on every run, so worktree reuse is a measured decision, not a guess
  • max_concurrent_readonly and max_concurrent_fix, per repository serialisation kept
  • Tests passed (worker) is written only on a real pass

Technical architecture and security

Built on strict invariants.

The same rules held in 0.2 and hold in 1.0. The orchestration features are built on top of them, never around them.

Zero runtime dependencies
The plugin, CLI, worker and dashboard use Node 22 and its standard library. No bundler, no framework, nothing to audit but the repository.
Durable journal
An append-only JSONL event log behind a single-writer worker lock. Ingress is fsynced and renamed before anything is acknowledged; replay rebuilds byte-identical state.
Isolated worktrees
Agent fixes run in a detached checkout at the ticket's recorded base commit, never in your working directory. The worktree is removed when the run ends.
Fail-closed gate
In strict mode, covered mutating tools are denied the moment the binding snapshot or the worker is unavailable. The gate never emits allow; your own Claude Code permissions always apply.

No plain secret is ever written to disk, and nothing secret goes in the status line. Session tokens are stored as hashes with a sliding seven-day expiry; quill ui --revoke clears them all.

Single-writer journal

Hooks write one JSON file per event and never read the journal. The worker ingests, journals, applies and republishes within its tick. A duplicate event id or source identity has no effect, so a crash mid-batch replays clean.

Fail-closed gate

PreToolUse reads one identity file, the heartbeat and the session's binding snapshot: no TOML, no network, no subprocess. In strict mode an unavailable snapshot denies covered writes. In the default nudge mode nothing is denied; Stop asks once which ticket the work belongs to.

Worktree isolation

An attempt-fix run gets git worktree add --detach at the recorded base commit. Permissions are explicit objects validated at submission and again at dispatch. Push and PR rights exist only as tokens the agent's environment is given.

What happens next

  1. Quill detects the repository and registers its main working tree privately. No quill init, no repo add, no config file.
  2. The worker starts and captures the current session. A ticket key in your prompt or branch binds the session without a command.
  3. Add a tracker when you want one: a [tracker] table and a token variable. Turn on import_assigned to pull your queue in.
  4. Give a repository a test command and attempt-fix runs become test-verified.

A few things worth knowing.

Does it clone repositories by itself?+

No. The resolver can tell that a ticket needs a clone and shows the remote, the target folder and the host check. It clones only after you confirm, from the dashboard or with quill repo clone KEY --confirm, and only from hosts in clone_hosts. The same remote is never cloned twice.

Can my lead run agents on my machine from a shared page?+

They can propose one. A Run agent edit on a two-way artifact page becomes a proposed run on your dashboard, naming the editor and the recipe. It runs only when you approve it, and the page's text reaches the agent as data, never as your instructions.

What does "Tests passed (worker)" mean?+

The worker, not the agent, ran your repository's test_command in the run's worktree after the agent finished, and it exited 0. The exit code, duration and output tail are kept on the run. If it failed, the agent got one repair turn and the gate ran again; a second failure produces no suggestion.

Is there a pre-warmed pool of worktrees?+

Not yet, on purpose. Every run records how long its worktree took to create. Recycling or pre-warming is deferred until those timings show it matters, and the decision is written down as an ADR either way.

Do I still need quill init and quill repo add?+

Not for the usual path. /session-quill:start and /session-quill:ui set everything up. init keeps the interactive setup and repo add registers extra repositories when you want to do it by hand.

What leaves my machine?+

Nothing, until you queue a run or publish. A run sends selected ticket content to your configured model provider. A publish sends only the fields of the projects you listed, through the same filter as exports. There is no telemetry.
