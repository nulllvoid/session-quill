# Session Quill 2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt the 2.0.0 PRD's five pillars and performance items inside the existing ADR contracts.

**Architecture:** Every feature extends an existing module and idiom. New event kinds are limited to `worktree` (ingress), `snapshot-tx`, `ci-observation` and `ci-proposal` (worker-only). Everything else is a field or an op on an existing kind. Each task records its decisions in its own ADR and its contract additions in its own subsection of `docs/DATA-CONTRACT.md` → "2.0.0 additions".

**Tech Stack:** Node ≥ 22 ES modules, `node:test`, no new dependencies; vanilla JS dashboard in `ui/`.

**Spec:** `docs/research/2.0.0/00-prd.md` (the PRD) as amended by `docs/research/2.0.0/01-gap-analysis.md` (how each requirement is adopted). Where they differ, the gap analysis wins.

## Global Constraints

- No new runtime or dev dependencies.
- Event kinds are kebab-case. A worker-only kind is listed in `WORKER_ONLY_KINDS` and is quarantined from ingress (R59); add its forged case to `tests/worker/ingress-trust.test.js`.
- Only the worker journals generated state (ADR 0001). The reducer stays pure: no clock reads beyond event times, no git, no file IO.
- No git and no network on the hook path (ADR 0021, `src/hooks/adapter.js` header). Hook p95 budget 200 ms (TRD).
- New record fields are local-only unless the task says otherwise: never add them to `src/export/sanitize.js`, `src/worker/notes.js`, the mirror or publishers. Where an export shows something new, it is a count. Extend `tests/export/privacy-sentinel.test.js` for every new local field holding paths, refs, test output, scopes or agent text.
- Scope grants, critical approvals and CI-fix approvals are dashboard-only owner actions (ADR 0028 §4, R59). Nothing auto-approves (ADR 0025).
- UI copy follows design system §6: no new run states; a critic's opinion is never called verification; "done" never implies merged or deployed; counts say what they count. All agent, tool and config text is escaped with `esc`/`attr`.
- Test files holding many adversarial shell strings stay under ~500 lines (an antivirus quarantines larger ones; see `tests/gate/guard-fixture.js`).
- Run targeted tests while working. Run `npm test` once at the end of each task; Windows timing tests `tests/hooks/autobind.test.js` "within the hook budget" and `tests/hooks/adapter.test.js` "p95 < 200 ms" are known flakes; rerun once before treating them as failures.
- UI changes: `node --test "tests/ui/*.test.js" "tests/export/*.test.js"`; asset changes: `node scripts/build-ui-assets.mjs --check`.
- Commit messages: conventional (`feat(scope): …`), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Secrets inside identifiers.** A token pasted into a commit message, Stop message, plan or tracker comment is redacted, but ids, hashes, SHAs, UUIDs and `write_paths` survive byte for byte, so source identities and dedupe still hold (Task 1).
2. **Checkpoint drift.** A state checkpoint written by an older reducer or package version, or whose offset no longer points at `last_event_id` (truncated or edited journal), is ignored and the worker replays fully (Task 2).
3. **Uncommitted work.** Restoring a snapshot, tearing down a ticket worktree or pruning never deletes uncommitted user work: restore takes a pre-restore snapshot; teardown skips dirty worktrees and never uses `--force` (Tasks 7, 8).
4. **Agent text across runs.** Failure records, context cards, critic findings and CI logs carry agent or tool text; only worker-structured fields cross into another run's prompt, and every text field passes the instruction filter and is escaped in the UI (Tasks 4, 10, 11, 12).
5. **Narrow, never widen.** Planned files, leases and dry-run preflight can only refuse or flag; nothing in them allows a call the 1.1 guard refused (Tasks 3, 9).
